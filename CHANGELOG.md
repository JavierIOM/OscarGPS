# Changelog

## [1.6.0] - 2026-11-04

### Added
- Wi-Fi status page on USB power. The board runs its own network, `OscarGPS`, with a page at
  `http://192.168.4.1` (and a catch-all DNS so phones open it as a sign-in page): sky plot,
  signal bars, satellite table, position with altitude, speed and course, the 10-character
  grid, fix type, HDOP/PDOP/VDOP, link and PC port, battery, uptime, free memory and NMEA
  checksum counts, updated every second. Dark theme with a light toggle.
- Wi-Fi follows the power source (`WIFI_AP_MODE` 1, the default): on 5 s after USB appears, off
  5 s after it goes, so the battery isn't spent on it. 0 never, 2 always.
- WPA2 password made from the hardware RNG on first boot and kept in NVS: different on every
  board, never in the source or the images. Shown on a new Wi-Fi page on the screen and in
  the USB log.
- `api` over USB serial prints the page's JSON, for testing without joining the network.
- Position, altitude, date, speed, course, fix type and PDOP/VDOP are now kept from RMC, GGA
  and GSA, and good and bad NMEA checksums are counted.

### Changed
- Flash use goes from 1.16 to 1.62 MB of the 3 MB app partition. With Wi-Fi and Bluetooth both
  up, 45 to 50 KB of heap is free (lowest seen 28 KB, during Wi-Fi start).

## [1.5.0] - 2026-11-04

### Changed
- The link label says why the board isn't linked. "COM11 closed": the PC answered, but nothing
  has its Incoming port open. "PC not found": no answer (off, asleep, out of range or Bluetooth
  off). Bluedroid reports both with the same failure status, so the dialler times the PC's SDP
  answer: about a second when it's there, the 5.12 s page timeout when it isn't
  (`PC_ANSWER_MS`). Replaces "use COM11", which was shown in both cases and read as if the
  board needed fixing. On 3 Nov that led to a re-pair, which deleted the port. Tested on 4 Nov:
  OscarWatch closed gave "COM11 closed" (answer in 147 ms), Bluetooth off gave "PC not found"
  (5140 ms), and reopening OscarWatch relinked in 7 s.
- "dialling" while a paired board redials, "not linked" only when nothing is paired.
- "Oscar linked" only with a fix. Linked without one reads "awaiting sats": on 4 Nov the label
  said linked while the GPS indoors had no fix, so OscarWatch had nothing to show.
- The USB log gives the reason and the SDP time on each change, then every 20th failure, and
  logs the link label whenever it changes (`Link label: ...`).
- Enclosure, from Javier's test fit of the cut box:
  - L2 loses its USB cut-out: the FireBeetle rests on L2, so it was all below the board.
  - The USB opening in L3 and L4 moves 3 mm towards the battery side (x 48.3 to 63.05) to
    line up with the socket.
  - L6 loses the small back-wall slot copied from the print. Not needed.

### Added
- README troubleshooting: removing and re-pairing the board in Windows deletes the Incoming
  port, which has to be added again.

## [Unreleased, folded into 1.4.1]

### Added
- `enclosure/`: laser-cut 3 mm acrylic lid (window on its own layer for opaque acrylic), 12
  glue-on clips for the screen and GPS copied from the printed lid, and a card/MDF glue jig.
  Generated by `make_lid.py`. No firmware change, so no version bump.
- `enclosure/`: layered plywood box, 8 layers of 3.6 mm ply (`box.scad`, exported by
  `make_box.py`), copying the printed base's battery bay, board pads and USB opening. Lid
  bolts into M3 nuts trapped in layer 7. Includes a 3D preview and a collision check.

## [1.4.0] - 2026-11-01

### Changed
- **The board now dials the PC** (`BT_DIAL_HOME`, on by default). Once paired, it connects to
  the PC's Incoming Bluetooth COM port, and redials after a restart, power loss or dropout,
  so the app holds one port open and never has to reconnect. Tested by restarting the board
  under an open COM11: data was back in 10 seconds with no action on the PC. The paired PCs
  come from the board's own bond list, so nothing is configured or hard-coded. A board with
  nothing paired offers its serial port the old way so it can be paired.
- Dialling runs in its own task, so the GPS, screen and USB output keep going while a dial to
  an absent PC times out.

### Added
- The screen names the COM port to use: "use COM11" when not linked, taken from the name
  Windows gives its serial service in SDP, so it follows Windows if the number changes.
  Windows only offers the service while an app has the Incoming port open, so the last name
  is kept in NVS and shown after a restart too. "dialling" before any name is known.
- "Paired PC" line in the boot check.

### Fixed
- The repeated "not linked" after every board restart. Each time, OscarWatch was retrying the
  dead Outgoing port about 30 times a second, and Windows' RFCOMM driver ended up failed (code
  10). The two looked linked; that's not proven.

## [1.3.1] - 2026-11-01

### Changed
- When no battery divider is found, the boot log gives the raw A0 reading, so a wiring fault
  (0 V: VCC leg or A0 wire not connected) can be told apart from a missing divider.

## [1.3.0] - 2026-10-31

### Added
- Retro BIOS boot screen when a screen is fitted, like the RAPT and weather displays: title
  bar, CPU/flash/Bluetooth MAC/I2C table, then a scrolling peripheral check with dot leaders.
  The results are real: GPS, display, battery sense, Bluetooth and the first NMEA sentence each
  report OK, NONE, FAIL, WAIT or the battery voltage. Adds about 5 seconds to boot; none
  without a screen.

### Removed
- The plain "OscarGPS / version" splash, which the BIOS screen replaces.

## [1.2.0] - 2026-10-31

### Added
- Screen pages in the style of an Icom ID-52's GPS screen: a sky plot (PRN at azimuth and
  elevation, reversed when in the fix, per-system used/in-view, HDOP) and per-satellite signal
  bars. Cycle: main 10 s, sky 5 s, signal 5 s, only while satellites are in view.
- Optional battery gauge from a 100k/100k divider on VCC to A0: percentage and icon on the main
  page, "USB" when on USB power, volts on the sky page. Leaves the screen alone without one.
- GSV and GSA parsing.

### Changed
- GSV now every second instead of every fifth, so the satellite pages are live.

## [1.1.0] - 2026-10-22

### Added
- Optional 128x64 I2C OLED on the GPS bus showing UTC, the 6-character Maidenhead grid,
  satellite count and Bluetooth link state. SSD1306 or SH1106 is detected at boot from the
  status byte (Meshtastic's probe), at 0x3C or 0x3D. A screen plugged in later is picked up
  within 5 seconds.
- Burn-in care: contrast 96 of 255, and the layout shifts by up to 2 px each minute.
- Redraws happen after each RMC, at the end of the NMEA burst, so the ~95 ms I2C transfer never
  delays a sentence.
- README troubleshooting for Windows Bluetooth COM ports that wedge with "cannot find the file
  specified".

### Changed
- CPU runs at 80 MHz instead of 240, the lowest Bluetooth allows, for battery life.
- The LED stays off when a screen is fitted.
- The time is tagged "UTC" on screen so nobody mistakes it for local time.
- Link label reads "Oscar linked" or "not linked".

## [1.0.1] - 2026-10-22

### Added
- MIT licence.
- README rewritten for anyone building one: other ESP32 boards, Linux pairing, the timing
  limits of NMEA, troubleshooting (including OscarWatch not reconnecting after a reboot).
- Prebuilt release images: a full image for `0x0` and an app-only image for `0x10000`.

### Changed
- `strip_paths.py` pre-script maps local build paths out of `__FILE__`, so the binary carries
  no home directory from the machine it was built on.
- I2C pins are now `I2C_SDA` / `I2C_SCL` defines at the top of `main.cpp`.
- `platformio.ini` no longer pins a COM port; PlatformIO auto-detects it.

## [1.0.0] - 2026-10-22

### Added
- Reads NMEA from an Adafruit Mini GPS PA1010D over I2C (0x10, SDA 21, SCL 22) and relays it
  over Bluetooth Classic SPP as `OscarGPS` and over USB serial at 115200.
- Checksum check on every sentence before it goes out; the PA1010D's bare-LF buffer padding is
  dropped, so it can't split a sentence.
- GPS configured at boot for RMC, GGA and GSA every second and GSV every fifth.
- Status lines on USB prefixed `#` (NMEA parsers skip them): boot info, I2C scan, fix gained and
  lost, Bluetooth client connect and disconnect.
- GPS re-probed every 5 s if it was missing at boot.
- LED: fast blink with no GPS on the bus, one flash a second while searching, solid with a fix.
